## D2 已实现的业务合同

1. `waiting_user` 是 Run 状态，Task 仍为 `in_progress`；界面显示“等待你决定”，不暗示 Pi 仍在自主执行。
2. Agent 的问题与人的回复分别保留为 `run.waiting_user` / `run.resumed` Event，并在任务详情显示“人工决定记录”。
3. 人可从 `ready` 或 `in_progress` 标记阻塞：活跃 Run 变 `interrupted`，Task 变 `blocked`，原因作为阻塞说明。
4. 人解除阻塞时必须填写解决说明：Task 回到 `ready`，说明留给下一轮 Run。
5. 人可取消任何非终态任务：活跃 Run 变 `canceled`，Task 变 `canceled`，原因保留在事件历史。
6. 阻塞/取消活跃 Run 时，服务端先暂停 Task capability，再请求 Pi abort；abort 失败会恢复 capability，且不会写入错误的 Task 状态。成功 abort 后才写 SQLite，防止迟到的 Agent Review 被接受。

## 边界与注意事项

- 仅操作当前 Pi Task 检出；上游或研究资料保持只读。
- 不运行 `next build`；开发使用 `next dev`，隔离 runtime 一律在 `.runtime/`。
- Task/Run SQLite 与 Pi JSONL 分离，仅以 `sessionId` 关联；不要重写对话 JSONL 来保存任务数据。
