## 破坏性变化与适配

### 1. `message_update` 改为 delta-only

Pi 0.84 的 JSON/RPC `message_update` 不再提供累计 `message`，也不再提供 `assistantMessageEvent.partial`。旧 Pi Task SSE 恰好删除了 `assistantMessageEvent`，只保留累计 `message`；升级后会把每个更新变成空事件，前端流式文本、Thinking 和 Tool Call 全部失效。

适配后的契约：

1. 服务端 SSE 只转发 `assistantMessageEvent` delta，并显式删除内部 SDK 事件仍携带的累计 `message` 和 provider `partial`，避免长回复在线路上出现二次增长；
2. 浏览器按 `contentIndex` 累积 `text_*`、`thinking_*`、`toolcall_*`；
3. `toolcall_delta` 只做可解析时的参数预览，`toolcall_end.toolCall` 为工具调用最终值；
4. `message_end.message` 始终覆盖为权威最终消息；
5. 页面刷新或 SSE 重连若发生在 `message_start` 之后，服务端先从 `agent.state.streamingMessage` 发送一次快照，再继续转发后续 delta，避免丢失重连前内容；
6. 保留累计 `event.message` 的短期前端回退，只为兼容本地热更新时已经打开的旧 SSE 连接。

相关实现：

- `lib/agent-event-projection.ts`
- `lib/assistant-message-stream.ts`
- `app/api/agent/[id]/events/route.ts`
- `hooks/useAgentSession.ts`

### 2. 认证取消信号

Pi 0.84 要求 provider API-key `login()` 收到具体 `AbortSignal`。Pi Task API-key 保存路由现已传入 `req.signal`，客户端断开时 provider 登录步骤可取消。OAuth 路由此前已经传递独立的取消信号，无需改变。

### 3. Theme 构造器要求完整回退色

0.84 的 `Theme` 构造器会立即派生 `thinkingMax` 和 `scrollbarThumb`。Pi Task 的无 ANSI Headless Theme 过去用空对象占位，现会在模块加载时崩溃。当前提供合法占位色，但所有输出方法仍覆盖为纯文本，不改变 Web UI 视觉。

### 4. `undici` 8.9.0 行为与安全更新

- 直接依赖同步到 Pi Coding Agent 0.84.1 使用的 8.9.0，确保 `setGlobalDispatcher()`、`install()` 与全局 fetch 来自同一实现。
- HTTP 代理测试已适配 8.9.0 的标准绝对 URI 转发；HTTPS 仍走 CONNECT；NO_PROXY、连接池刷新和代理切换保持验证。
- 升级清除了审计中的全部 `undici` 与 Pi 内部 `brace-expansion` 漏洞项。升级前为 7 项漏洞（6 high、1 moderate）；升级后为 4 项 high，剩余项属于既有 Next/PostCSS/Sharp/Nanoid 依赖树，不在本阶段范围。

## 回滚方案

代码回滚（本阶段独立提交后）：

```bash
git revert <阶段一提交>
npm ci --include=dev --ignore-scripts
```

如果仅需临时恢复依赖，可把四个 Pi 包和直接 `undici` 恢复到 `0.83.0` / `8.5.0`，同时恢复两个 lockfile；但这会重新引入本次已清除的 `undici` 与 `brace-expansion` 安全问题，不建议长期使用。

数据回滚无需迁移：本阶段不改 Session v3、Pi Task SQLite schema 或默认数据路径。若之后进入实际 macOS 升级，必须先停止服务并确认无活动 Run；程序构建可恢复升级器保存的上一份 `.next`，`~/.pi/agent` 与 `~/.pi-task` 必须原样保留。SQLite 人工备份/恢复时，服务停止后同时处理主文件及存在的 WAL/SHM。
