# Pi Task

[English](./README.md) · [简体中文](./README.zh-CN.md) · [日本語](./README.ja.md)

> **Превратите диалог с ИИ в работу, которую можно продолжить, проверить и принять.**

Pi Task — локальное рабочее пространство для задач, построенное вокруг диалога в [Pi](https://github.com/badlogic/pi-mono). Выберите один рабочий каталог, обсуждайте задачу естественным языком и формализуйте только ту работу, которой действительно нужны устойчивый план, история выполнения, доказательства проверки и приёмка человеком.

**Сначала диалог · Один рабочий каталог · Решения остаются за человеком · Локальный запуск из исходного кода**

![Pi Task превращает диалог в проверяемое соглашение о задаче](./docs/assets/pi-task-task-framing.png)

*Полностью изолированное вымышленное рабочее пространство в китайской локализации. Оно не содержит реальных Session, Task, учётных данных или локальных путей.*

## Зачем нужен Pi Task

История чата показывает, что было сказано, но для работы с реальным результатом нужны ответы и на другие вопросы:

- Что именно требуется получить в итоге?
- Какие источники и ограничения считаются основными?
- Работа прервана, заблокирована или ждёт решения человека?
- Что изменено, как это проверено и что осталось неподтверждённым?
- Кто решает, что работа действительно завершена?

Pi Task связывает эти ответы с исходным диалогом Pi, не заставляя сначала переходить в отдельную систему управления проектами.

```text
Выбрать рабочий каталог
→ Обсудить работу естественным языком
→ Сохранить или подтвердить соглашение о задаче, когда оно действительно нужно
→ Выполнять, приостанавливать, принимать решения и восстанавливать работу в том же диалоге
→ Проверить артефакты и доказательства
→ Принять результат или вернуть его на доработку
```

Простые вопросы остаются простыми диалогами. Task появляется только тогда, когда полезна долговечная фиксация работы.

## Чем Pi Task отличается

- **Один рабочий каталог:** диалог, файлы, фактически загруженные источники правил и Task Board относятся к одной локальной области.
- **Task возникает из разговора:** перед началом не требуется создавать Project или заполнять длинную форму.
- **Решения человека не обходятся:** нажатие на вариант отвечает на вопрос, но не запускает Run и не разрешает внешнее действие автоматически.
- **Task и Run разделены:** окончание потока Agent не считается завершением работы. Только человек может принять Review или завершить Task.
- **Работу можно восстановить:** сохраняются прерывания, блокировки, отмена, продолжение в той же Session, артефакты и доказательства Review.
- **Pi остаётся центром:** просмотр сессий, чат в реальном времени, модели, Skill, файлы и Git worktree доступны рядом с процессом задач.

## Запуск из исходного кода

**Требование:** Node.js 22.19.0 или новее.

```bash
git clone https://github.com/adamhillaby266-blip/pi-task.git
cd pi-task
npm ci --include=dev --ignore-scripts
npm run dev
```

Откройте <http://127.0.0.1:30142>.

Сейчас Pi Task выпускается как исходный код для разработчиков, а не как пользовательский установщик или npm-пакет. Не используйте унаследованные команды `npx`, глобальную установку или `pi-web`. Изолированная разработка, проверки и локальная сборка для macOS описаны в [Developing Pi Task from source](./docs/development.md).

## Текущая граница использования

Pi Task предназначен для локального использования разработчиком.

- Исходный launcher принимает только loopback-хосты (`127.0.0.1` или `localhost`).
- Не поддерживаются LAN, обратный прокси, хостинг, Docker, npm-публикация, подписанные настольные приложения, автообновление и GitHub Release.
- Не используйте Pi Web и Pi Task одновременно с одной активной Pi Session.
- Multi-Agent не включён по умолчанию. Основной сценарий остаётся одним диалогом с явными решениями человека.

## Локальные данные и конфиденциальность модели

Приложение и состояние Task хранятся локально, но запросы к модели обрабатывает Provider, настроенный в Pi.

- Сессии Pi, настройки моделей и аутентификация: `~/.pi/agent`
- Task, Run, артефакты, Review и события: `~/.pi-task/pi-task.sqlite`
- Рабочие файлы: выбранный рабочий каталог и восстановленные каталоги Session

Промпты и действия инструментов могут передавать выбранное содержимое настроенному Provider. Учитывайте его политику обработки данных.

Для тестов задавайте `HOME`, `TMPDIR`, `PI_CODING_AGENT_DIR` и `PI_TASK_DATA_DIR` внутри игнорируемого каталога `.runtime/`. Не используйте реальные учётные данные, неопубликованные материалы или данные компании в fixture.

## Проверки для разработки

```bash
node_modules/.bin/tsc --noEmit
npm run lint
node --test lib/*.test.mjs components/tasks/*.test.mjs
```

Не запускайте `next build` или `npm run build` в обычном цикле разработки: они записывают `.next/` и могут помешать `npm run dev`.
