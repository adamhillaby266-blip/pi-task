# Pi Task

[English](./README.md) · [简体中文](./README.zh-CN.md) · [日本語](./README.ja.md)

> Локальное рабочее пространство с задачами для разработчиков, использующих Pi. Pi Task сохраняет диалог Pi в центре работы и добавляет долговечные Task, Run, артефакты, Review и подтверждение человеком.

Pi Task распространяется только как исходный код для разработчиков, а не как пользовательский установщик. Для повседневного сценария Gate D и локального пути Gate E на macOS есть записи приёмки; подписанное приложение, автообновление, хостинг и внешняя дистрибуция намеренно не входят в область проекта.

## Возможности

- Преобразует сохранённый диалог Pi в Task с контрактом, подтверждённым человеком.
- Отделяет жизненный цикл Task/Run от потокового состояния Agent: только человек может принять Review или завершить Task.
- Поддерживает прерывание, блокировку, отмену, восстановление в той же Session, артефакты и доказательства Review.
- Предоставляет просмотр локальных сессий Pi, чат в реальном времени, управление моделями и Skill, просмотр файлов и переключение Git worktree.

## Граница использования

Pi Task предназначен только для локального использования разработчиком.

- Исходный launcher принимает только loopback-хосты (`127.0.0.1` или `localhost`); документированные пути разработки и macOS используют `127.0.0.1:30142`.
- Не поддерживаются доступ из LAN, обратный прокси, публикация в интернете, Docker, npm-публикация, настольные установщики и GitHub Release.
- Не используйте Pi Web и Pi Task одновременно с одной активной Pi Session.
- После отправки промпта Pi Task может обратиться к Provider модели, настроенному в локальном Pi. Обрабатывайте промпты, результаты инструментов и файлы выбранного рабочего каталога в соответствии с политикой данных этого Provider.

## Запуск из исходного кода

**Требование:** Node.js 22.19.0 или новее.

```bash
git clone <repository-url> pi-task
cd pi-task
npm ci --include=dev --ignore-scripts
npm run dev
```

Откройте <http://127.0.0.1:30142>. Этот репозиторий не является npm-пакетом для конечных пользователей: не используйте унаследованные команды `npx`, глобальную установку или `pi-web` для запуска Pi Task.

Инструкции по изолированной разработке, проверкам и границе сборки macOS см. в [Developing Pi Task from source](./docs/development.md).

## Локальные данные и безопасность

- Сессии Pi, настройки моделей и аутентификация по умолчанию находятся в `~/.pi/agent`. Pi Task читает эти данные, а действия с сессиями, моделями или аутентификацией могут записывать локальное состояние по вашему запросу.
- База данных Task по умолчанию находится в `~/.pi-task/pi-task.sqlite`. Перед ручным резервным копированием остановите Pi Task.
- Для тестов задавайте `HOME`, `TMPDIR`, `PI_CODING_AGENT_DIR` и `PI_TASK_DATA_DIR` внутри игнорируемого каталога `.runtime/`. Не используйте реальные учётные данные, неопубликованные материалы или данные компании в fixture.
- `.gitignore` — лишь страховка, а не средство хранения секретов. Перед коммитом проверяйте `git status` и не добавляйте данные Pi, SQLite, JSONL, файлы окружения, журналы и закрытые ключи.

## Проверки

После установки зависимостей выполните из корня репозитория:

```bash
node_modules/.bin/tsc --noEmit
npm run lint
node --test lib/*.test.mjs components/tasks/*.test.mjs
```

Не запускайте `next build` или `npm run build` в обычном цикле разработки: они записывают `.next/` и могут помешать `npm run dev`.
